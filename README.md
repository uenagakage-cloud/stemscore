# StemScore — 楽器別の音源分離と自動採譜

YouTube / Spotify / Google Drive の URL、または手元の音声・動画ファイルを入力すると、ブラウザ上で次のことができます。

- **パート分離**: ボーカル / ドラム / ベース / その他（6パートモデルではギター / ピアノも）に分けます（Demucs を使用）
- **楽曲解析**: キー（候補つき）、BPM、拍の位置、コード進行を推定します
- **自動採譜**: 各パートを楽譜（MusicXML）と MIDI にします（Basic Pitch を使用。ドラムは独自のオンセット検出で処理）

## セットアップと起動 (Windows)

1. `setup.bat` を実行します（初回のみ。PyTorch などを入れるため数 GB あり、数分かかります）
2. `start.bat` を実行すると、ブラウザで http://127.0.0.1:8765 が開きます

※ 最初の分離では Demucs のモデル（約 80MB〜300MB）がダウンロードされます。
※ GPU（CUDA）がなくても CPU だけで動きます。3〜4 分の曲なら、標準モデルで数分程度です。

## スマホで使う

分離や採譜などの重い処理はすべてこの PC（サーバー）で行います。スマホはブラウザで操作して再生するだけです。

1. PC で `start.bat` を実行する（同じ Wi-Fi 内の端末からアクセスできるモードで起動します）
2. PC の画面右上の「📱 スマホで開く」を押す（黒い画面にも QR コードが表示されます）
3. PC と同じ Wi-Fi につないだスマホのカメラで QR コードを読み取る
4. 必要なら、ブラウザの共有メニューから「ホーム画面に追加」するとアプリのように使えます

- 初回だけ、QR に含まれるアクセスキーが必要です（以後はスマホに保存されます）。キーを知らない端末は利用できません。キーは「スマホで開く」画面から再発行できます。
- スマホから動画や音声ファイルをアップロードできます（アップロードの進み具合を表示します）。処理中にスマホの画面を閉じても、処理はサーバーで続きます。
- 再生用の音声は軽い AAC（WAV の約 1/8 のサイズ）で配信します。WAV は「⬇WAV」からダウンロードできます。
- スマホ用の画面では、下部の「追加 / 履歴 / 曲」タブとミニプレイヤーで操作します。ループ区間は A・B ボタンで設定します。
- 初回起動時に Windows のファイアウォールの確認が出たら「許可」を選んでください。学校や公共の Wi-Fi は端末同士の通信を禁止していることが多く、その場合はつながりません（スマホのテザリングや自宅の Wi-Fi を使ってください）。
- この PC からのみ使いたい場合は `.venv\Scripts\python -m app.server --local` で起動します。

## クラウドで使う（Render）

[Render](https://render.com) にデプロイすると、PC を起動していなくても、いつでも同じ URL（`https://<サービス名>.onrender.com`）で使えます。

### 料金と性能の目安
- AI による分離には 2GB 以上のメモリが必要です。Render の Free / Starter（512MB）では動かないので、**Standard（2GB・月 $25 程度）以上**を使います。Pro（4GB・2CPU）にすると速くなります
- 履歴を残すディスク（10GB）は月 $2.5 程度かかります
- GPU はないので、3〜4 分の曲の分離に 10〜15 分ほどかかります（Standard の場合）
- Render のサーバーからは YouTube の取得がブロックされることがあります。曲は **Google ドライブの共有リンク**か、**スマホからのファイルアップロード**で渡すのが確実です

### デプロイ手順（最初の 1 回）
1. このフォルダを GitHub のリポジトリ（非公開で可）に push する
2. Render にログインし、**New + → Blueprint** → GitHub を連携してリポジトリを選ぶ
3. `render.yaml` の内容（Web サービス・ディスク・アクセスキー）が表示されるので **Apply**。初回のビルドは 10〜20 分ほどかかります
4. Render の画面で stemscore サービス → **Environment** を開き、`STEMSCORE_ACCESS_KEY` の値を確認する
5. スマホなどで `https://<サービス名>.onrender.com/?key=<アクセスキー>` を開く（一度開けばブラウザに保存されます）

コードを更新したら GitHub に push すると、Render が自動で作り直します。

## クラウドで使う（この PC がなくても使える: Google Colab）

PC を起動していなくても、スマホなどから Google Colab（Google の無料のクラウド。GPU 付き）で StemScore を動かせます。処理結果と曲は Google ドライブに保存されます。

### 準備（最初の 1 回だけ）
1. PC で `.venv\Scripts\python toolsuild_cloud.py` を実行すると、`dist/` に `StemScore_cloud.zip` と `StemScore_クラウド起動.ipynb` ができます
2. Google ドライブに「StemScore」フォルダを作り、この 2 つを入れます
   （アプリを更新したら、`build_cloud.py` をもう一度実行して zip を置き換えます）

### 使うとき
1. Google ドライブの「StemScore」→「StemScore_クラウド起動.ipynb」を開く（Google Colaboratory で開く）
2. 「▶ StemScore を起動」を押す。ドライブへのアクセス許可を求められたら許可する
3. 表示される「StemScore を開く」を押す（同じブラウザ・同じ Google アカウントでだけ開けるリンクです）
4. 使い終わったら「■ 停止」を押す

- 曲は Google ドライブの「曲」フォルダに入れると、StemScore の「Drive」タブから選べます（共有設定は不要です）
- Colab のタブは開いたままにしてください。閉じたり長時間操作しないと停止します（処理結果はドライブに残ります）
- 無料枠では、GPU を使える時間に上限があります。上限に達すると CPU で動くので遅くなります
- 処理結果は 1 曲あたり約 200MB をドライブに使います。不要な曲は履歴から削除してください

## 主な機能

| 機能 | 内容 |
|---|---|
| 入力 | YouTube などの URL（yt-dlp を使用）、Spotify のトラック URL（曲名とアーティストから YouTube を検索）、Google Drive の共有リンク、ファイルのドラッグ＆ドロップ |
| 分離モデル | 4パート標準 / 6パート（ギター・ピアノ追加）/ 4パート高品質 / 簡易分離（AI モデル不要・品質は低め） |
| 区間指定 | 曲の一部だけを処理して時間を短縮 |
| ミキサー | パートごとのミュート・ソロ・音量、ワンクリックのカラオケ、WAV のダウンロード |
| 練習向け | 音程を変えずに再生速度を変える（50〜150%）、A-B ループ（波形上で Shift+ドラッグ）、拍に合わせたメトロノーム |
| コード | 現在のコードと次のコードを表示、タイムライン表示 |
| 楽譜 | パートごとの楽譜と総譜、コード記号つき、ピアノは大譜表、ドラムは打楽器譜 |
| 読みやすさ | 音符の下に音名（C D E … / C4 のように高さ付きも可）、音名ごとの色分け、ドラムは K・S・H などの記号、「楽譜の読み方」の説明、ピアノロールの四角の中にも音名 |
| 移調 | ±12 半音。B♭管・E♭管・F管・ギター記譜のプリセットあり |
| ピアノロール | 再生に合わせてスクロール、採譜した音を重ねて再生し、精度を耳で確かめられる |
| 再採譜 | 感度を変えて、パートごとに採譜をやり直す |
| 書き出し | MusicXML（MuseScore などで編集可）、MIDI（元音源とタイミングを揃えてあるので DAW でそのまま並べられる）、印刷 / PDF、すべてをまとめた ZIP |
| 音域 | パートごとの最低音と最高音（ボーカルの音域チェックなどに使える） |

## 構成

```
app/
  server.py      FastAPI の Web サーバー / API
  remote.py      スマホからのアクセス (アクセスキー・QR コード)
  config.py      環境ごとの設定 (保存先・クラウドモード・曲フォルダ)
  jobs.py        ジョブのキューと処理パイプライン
  source.py      URL からの取得 (yt-dlp) / ffmpeg での変換
  analysis.py    BPM・キー・コードの推定 (librosa)
  separate.py    音源分離 (Demucs)
  transcribe.py  採譜 (Basic Pitch / ドラムのオンセット検出)
  notation.py    MIDI / MusicXML の生成 (pretty_midi / music21)
  static/        フロントエンド (楽譜の描画には OpenSheetMusicDisplay を使用)
data/jobs/       処理結果（ジョブごとのフォルダ）
Dockerfile        クラウド (Render など) 用のコンテナ定義
render.yaml       Render の Blueprint 設定
tools/
  StemScore_モデル取得.ipynb   Colab でモデルを取得して Drive に保存するノートブック
  build_cloud.py              クラウド (Colab) 用の zip と起動ノートブックを dist/ に作る
```

## ネットワークについて（学校・会社など制限のあるネットワーク）

### プロキシ
Windows にプロキシ（自動構成スクリプト / PAC を含む）が設定されている場合、起動時に自動で検出して使います。そのプロキシに接続できないネットワーク（自宅など）では、直接接続します。

### YouTube が使えないとき: Google Drive 経由で音源を渡す
PC のネットワークで YouTube が遮断されていても、Google Drive に接続できれば次の方法で処理できます。

1. スマホなどで曲の動画・音声を用意し、Google ドライブに入れる
2. Drive でそのファイルの共有設定を「リンクを知っている全員（閲覧者）」にして、リンクをコピーする
3. StemScore の URL 欄にそのリンクを貼り付けて開始する（PC が Drive からダウンロードして処理します）
4. ログに「ダウンロード完了」と出たら、共有設定を「制限付き」に戻して大丈夫です

スマホと PC が同じ Wi-Fi なら、スマホの「ファイル」タブから直接アップロードすることもできます。

### 分離モデルの配布元に接続できないとき: Drive 経由でモデルを取り込む
分離モデルは `dl.fbaipublicfiles.com` からダウンロードされます。ここに接続できないと、まだ PC にないモデルは使えません（画面のモデル名に「（未取得）」と表示されます）。その場合は Google Colab（Google のクラウド）で取得して Drive 経由で取り込みます。

1. `tools/StemScore_モデル取得.ipynb` を Google ドライブにアップロードし、「アプリで開く → Google Colaboratory」で開く
2. ▶（実行）を押す。Google アカウントへのアクセス許可を求められたら許可する
3. 1〜2 分で、ドライブの `StemScore_models` フォルダにモデル（5 ファイル・約 380MB）が保存され、最後にリンクが表示される
4. StemScore の左側（スマホでは「追加」タブ）の「分離モデルの追加」を開き、表示されたリンクをすべて貼り付けて「モデルを取り込む」を押す
5. すべてのモデルに ✔ が付いたら完了。ドライブの `StemScore_models` フォルダは削除して構いません

- 取り込むとき、ファイルが壊れていないか（公式のハッシュ値と一致するか）を自動で確認します。
- `.th` ファイルを手元に持っている場合は、「分離モデルの追加」から直接選んで取り込むこともできます。
- 取り込んだモデルは `%USERPROFILE%\.cache\torch\hub\checkpoints` に保存されるので、一度取り込めば以後はオフラインでも使えます。

| モデル | 必要なファイル |
|---|---|
| 4パート 標準 (htdemucs) | `955717e8-8726e21a.th` |
| 6パート (htdemucs_6s) | `5c90dfd2-34c22ccb.th` |
| 4パート 高品質 (htdemucs_ft) | `f7e0c4bc-ba3fe64a.th` `d12395a8-e57c48e6.th` `92cfc3b6-ef3bcb9c.th` `04573f0d-f3cf25b2.th` |

### AI モデルがまったく使えないとき
分離モデルで「簡易分離」を選ぶと、AI モデルなしで処理できます（品質は低めです）。

## 注意

- 自動採譜は完璧ではありません。叩き台として使い、MusicXML を MuseScore などで仕上げるのがおすすめです。
- Spotify の音声は DRM で保護されているため、直接は取得しません。
- 著作権のある音源は、権利者の許可がある範囲か、私的な練習・学習の範囲で使ってください。
